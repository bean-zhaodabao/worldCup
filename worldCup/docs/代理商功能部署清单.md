# 代理商功能部署清单

> 对应方案：`代理商功能开发方案.md`
> 更新时间：2026-10-23

---

## 一、部署前准备

1. 备份云数据库；
2. 确认当前 `users.username`、`orders.orderNo` 没有重复数据；
3. 确认 uniCloud 服务空间为阿里云（项目使用 `uniCloud-alipay`）。

---

## 二、上传云函数

在 HBuilderX 中右键 `uniCloud-alipay/cloudfunctions`，上传所有修改和新增的云函数。

### 修改的云函数

| 云函数 | 修改内容 |
|--------|---------|
| `user-auth` | 支持代理登录，返回 role/agentCode/commissionRate |

| `user-match` | 限制 role=user |
| `user-wallet` | 限制 role=user |
| `admin-user` | 创建用户支持所属代理；列表返回代理；修复充值分支被创建分支拦截 |
| `admin-order` | 支持按代理筛选；订单返回代理名 |
| `admin-config` | 新增代理佣金配置项 |
| `init-db` | 初始化代理佣金配置 |
| `admin-category` / `admin-config` / `admin-log` / `admin-login` / `admin-match` / `admin-order` / `admin-play` / `admin-report` / `admin-settle` / `admin-user` 的 `utils.js` | `verifyToken` 增加 `role === 'admin'` 校验 |

## 三、配置 URL 化

在 uniCloud 控制台为以下云函数配置 URL 化（和现有 `/admin-user` 方式一致）：

- `/admin-agent`
- `/admin-agent-commission`
- `/admin-sms`

> `agent-*`、`sms-job` 是移动端/定时器调用的，不需要 URL 化。

## 四、创建集合与索引

首次使用前，在 uniCloud 控制台创建以下集合（或先写入一条数据自动创建）：

- `agent-commission-records`
- `agent-commission-settlements`
- `agent-wallet-logs`
- `sms-config`
- `sms-tasks`
- `sms-logs`

### 必须创建的索引

| 集合 | 索引字段 | 类型 | 说明 |
|------|---------|------|------|
| `users` | `username` | 唯一 | 登录、创建查重 |
| `users` | `agentCode` | 唯一（稀疏） | 代理编号 |
| `users` | `agentId + status + createTime` | 普通 | 代理查用户 |
| `orders` | `orderNo` | 唯一 | 订单号 |
| `orders` | `userId + createTime` | 普通 | 用户订单 |
| `orders` | `agentId + commissionStatus + createTime` | 普通 | 佣金任务扫描 |
| `orders` | `agentId + createTime` | 普通 | 代理订单 |
| `agent-commission-records` | `agentId + orderId` | **唯一** | 佣金幂等，必须 |
| `agent-commission-records` | `agentId + status + createTime` | 普通 | 代理佣金列表 |
| `agent-commission-settlements` | `agentId + status + createTime` | 普通 | 结算批次 |
| `agent-wallet-logs` | `agentId + createTime` | 普通 | 佣金流水 |
| `sms-tasks` | `orderId + type` | **唯一** | 一单只发一次 |
| `sms-tasks` | `status + nextRetryAt` | 普通 | 短信任务扫描 |
| `sms-logs` | `createTime` | 普通 | 发送日志 |
| `sms-logs` | `taskId` | 普通 | 重发/排查 |

> `agent-commission-records` 的 `agentId + orderId` 唯一索引是防止重复计佣的关键，务必创建。创建前先确认没有重复数据。

## 五、配置定时器

`agent-commission-job/config.json` 已配置每 10 分钟触发：

```json
{
  "triggers": [
    {
      "name": "timer",
      "type": "timer",
      "config": "0 */10 * * * * *"
    }
  ]
}
```

上传云函数时勾选「上传触发器」或到控制台确认定时器已生效。

- `agent-commission-job`：每 10 分钟；
- `sms-job`：每分钟。

> 建议在 uniCloud 控制台把 `agent-commission-job` 的超时时间调整为 60 秒，避免单批订单较多时超时；任务本身是幂等的，超时后下一轮会继续处理。`sms-job` 建议 30 秒。

## 六、初始化配置

调用一次 `init-db` 云函数，会自动补齐：

- `agentCommissionEnabled` = `true`
- `agentDefaultRate` = `2.5`
- `agentCommissionConfirm` = `manual`

也可以到管理端「系统配置」手动修改。

### 短信配置

执行 `init-db` 后，会创建一条默认短信配置：

- 签名：`甘肃食为天餐饮管理`
- 模板 CODE：`SMS_512616834`
- 模板内容：`用户${name}有新的订单！`
- 接收手机号：`18298380835`
- 开关：默认关闭

部署后到管理端「短信通知」页面：

1. 填写 **AccessKey ID** 和 **AccessKey Secret**（RAM 子账号）；
2. 确认签名、模板 CODE、接收手机号；
3. 点击「发送测试短信」；
4. 测试成功后打开「短信开关」；
5. 用户下注后，`sms-job` 会在 1 分钟内发送。

> AccessKey Secret 只存在服务端，管理端只显示掩码。不要把它提交到代码仓库。

## 七、上线后验证

1. 管理端「代理商管理」创建测试代理，设置佣金比例；
2. 管理端「用户管理」创建测试用户，所属代理选测试代理；
3. 用测试用户登录移动端，下注一笔；
4. 等待赛事结算（或管理端手工结算）；
5. 管理端「佣金结算」点击「重算佣金」；
6. 检查佣金记录金额 = 下注额 × 代理比例；
7. 勾选佣金记录 → 确认入账；
8. 创建结算批次 → 标记已支付；
9. 用代理账号登录移动端，确认只能看到自己的用户、订单、佣金；
10. 用代理 Token 调管理端接口，确认返回 403；
11. 用普通用户 Token 调管理端接口，确认返回 403；
12. 在「短信通知」页发送测试短信，确认能收到；
13. 用测试用户下注，确认 1 分钟内收到「用户xxx有新的订单！」短信；
14. 查看短信发送日志，确认手机号已脱敏；
15. 关闭短信开关后再下注，确认不再发送。

## 八、常见问题

### 1. 代理登录后仍进入赛事首页

检查：
- `user-auth` 是否已上传；
- 登录返回是否包含 `role: "agent"`；
- 本地 `userInfo` 是否缓存了旧数据，退出重登。

### 2. 代理端看不到数据

检查：
- 用户的 `agentId` 是否已分配；
- 订单是否在下单时写入了 `agentId`（旧订单没有该字段，不会显示）；
- 历史订单不会追溯计佣。

### 3. 佣金不生成

检查：
- `agentCommissionEnabled` 是否为 `true`；
- 订单状态是否为 `settled`；
- 订单 `commissionStatus` 是否为 `none`；
- 代理 `commissionRate` 是否大于 0；
- `agent-commission-job` 定时器是否执行，或手动点击「重算佣金」。

### 4. 佣金重复

检查 `agent-commission-records` 的 `agentId + orderId` 唯一索引是否创建成功。

### 5. 保存短信配置提示「不支持的请求方法」

按顺序检查：

1. `admin-sms` 云函数是否已重新上传（本次已兼容 `POST` / `PUT` / 空路径 / `OPTIONS` 预检）；
2. URL 化 `/admin-sms` 的请求方法是否允许 `GET, POST, PUT, OPTIONS`；
3. 管理端是否已重新构建并部署（保存配置已从 `PUT` 改为 `POST`）；
4. 如果仍报错，错误信息会带上实际方法和路径，例如 `不支持的请求方法: POST /admin-sms`，把这一行发出来即可定位。

### 6. 点「发送测试短信」却提示「请至少配置一个接收手机号」

这是 URL 化网关把函数名前缀去掉导致的：

- 浏览器请求 `/admin-sms/test`；
- 云函数实际收到的是 `/test`；
- 旧解析误把 `test` 当成空 action，走进了「保存配置」分支，于是报手机号错误。

已修复：`admin-sms` 现在同时兼容 `/admin-sms/test` 和 `/test`，并且用请求体区分「保存配置」和「测试发送」。重新上传 `admin-sms`、重新构建管理端即可。

### 7. 打开「短信通知」提示 500

原因是 GET 请求的 `event.body` 是空字符串，旧代码对空字符串执行 `JSON.parse('')` 抛异常。已修复为仅在 `event.body` 非空时才解析。

重新上传 `admin-sms`、`admin-agent`、`admin-agent-commission` 即可。

### 8. 接口返回 OK，但手机收不到短信

先看阿里云控制台签名状态：

- `可用-异常` + `运营商状态：未报备`：签名在运营商侧未报备，运营商会拦截短信，接口仍可能返回 `OK`。
- `运营商状态：报备中`：材料已提交，等待运营商审核；审核期间短信仍可能被拦截，**不需要重复提交**。
- `运营商状态：已报备 / 报备成功`：可以正常下发。
- 处理方式：短信服务 → 国内消息 → 签名管理 → 该签名 → 完成「运营商报备 / 签名报备」，按提示提交企业资质、业务场景、模板、授权书等材料。
- 报备审核通常需要 1~3 个工作日，状态变为「已报备」后再测试。
- 同时确认模板状态是「已通过」，且模板与签名匹配。
- 测试仍失败时，到阿里云「发送记录」用手机号 + 日期 + BizId 查询具体失败原因。

> 代码里的「已受理」只代表阿里云接收了请求，不代表运营商已经下发。

### 9. 代理商管理 / 佣金结算 提示 404

404 是 URL 化路由没有配置，不是云函数代码报错。

到 uniCloud 控制台 → 云函数 → URL 化，为下面两个函数添加路径：

| 云函数 | URL 化路径 | 请求方法 |
|--------|-----------|---------|
| `admin-agent` | `/admin-agent` | GET, POST, PUT, PATCH, DELETE, OPTIONS |
| `admin-agent-commission` | `/admin-agent-commission` | GET, POST, PUT, PATCH, DELETE, OPTIONS |

配置后不需要重新构建管理端，刷新页面即可。

> 短信页能用，说明 `/admin-sms` 已配置；代理商和佣金页需要分别配置上面两个路径。

### 10. 系统配置保存后刷新恢复

可能原因：

- 管理端用 `PUT` 保存，URL 化网关只放行 `GET/POST`，请求没有真正进入云函数，但前端拿到了空响应误以为成功；
- `system-config` 里同一个 `key` 有重复记录，旧逻辑只更新第一条，刷新后读到另一条旧值。

已修复：

- `admin-config` 同时接受 `POST` / `PUT`；
- 更新同一 `key` 的所有记录；
- 保存后重新读取数据库校验，校验失败会返回错误，不再“假成功”。

部署：重新上传 `admin-config`，重新构建管理端（保存已改为 `POST`）。
